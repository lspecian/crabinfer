<objective>
Implement the Marlin-style fused dequant+GEMM CUDA kernel for GPTQ/AWQ INT4 inference, targeting 1.5-2x throughput improvement over the naive dequant-then-matmul path on RTX 3060.

Purpose: QLOAD-03 — the fused kernel eliminates the intermediate FP16 weight materialization, directly dequantizing INT4 packed weights into Tensor Core registers during GEMM. This is the single highest-impact performance optimization for quantized model serving.
Output: Marlin CUDA kernel in paged_attention.cu, KernelBackend trait method, CudaBackend implementation, weight reformat in quantization.rs, forward dispatch, and model-load-time activation.
</objective>

    **Part A: Marlin CUDA kernel (in paged_attention.cu)**

    Add after the existing `gptq_dequant_f32` kernel:

    ```cuda
    // Simplified Marlin-style fused dequant+GEMM kernel for sm_86 (Ampere).
    //
    // Each thread block handles a 16x64 output tile.
    // Weights are pre-reformatted into [K/16, N/64, 128] tile layout.
    // The kernel loads weight tiles, dequantizes INT4 to FP16, and accumulates
    // via FP16 FMA (not full Tensor Core MMA — that's a Phase 2 optimization).
    //
    // This is simpler than the full Marlin kernel but still fused: no intermediate
    // dequantized weight tensor is materialized in global memory.
    ```

    Implement `marlin_gemm_f16` as an `extern "C" __global__` kernel:
    - Grid: (N/64, M, 1) where M = batch size, N = out_features
    - Block: (256, 1, 1) — 8 warps per block
    - Each block computes a [1, 64] output tile (one batch row, 64 output columns)
    - Loop over K in steps of 16:
      - Load 16x64 weight tile from reformatted qweight (128 u32 values)
      - Dequantize: extract INT4 from u32, subtract zero point, multiply by scale
      - Multiply by input activation and accumulate
    - Write output tile to global memory
    - Shared memory: load input tile [1, 16] and weight tile [16, 64] for reuse

    Signature:
    ```cuda
    extern "C" __global__ void marlin_gemm_f16(
        __half* __restrict__ output,           // [M, N]
        const __half* __restrict__ input,      // [M, K]
        const unsigned int* __restrict__ qw,   // [K/16, N/64, 128] Marlin tile layout
        const __half* __restrict__ scales,     // [K/group_size, N]
        const unsigned int* __restrict__ qzeros, // [K/group_size, N/8]
        int M, int N, int K, int group_size
    );
    ```

    IMPORTANT: Do NOT use `mma.sync` PTX instructions in Phase 1 — they require `-arch=sm_86` NVRTC flag and careful register management. Use standard FP16 FMA (`__hfma`) instead. This is still fused (no global memory intermediate) and avoids NVRTC compilation issues. The full Tensor Core MMA path is a Phase 2 optimization.

    **Part A: Marlin weight reformat (in quantization.rs)**

    Replace the `reformat_for_marlin` stub with the actual implementation:

    ```rust
    pub fn reformat_for_marlin(&mut self, backend: &dyn KernelBackend) -> Result<bool> {
        // Only reformat on CUDA backend
        if backend.name() != "cuda" { return Ok(false); }

        let (pack_rows, out_features) = self.qweight.dims2()?;
        let in_features = pack_rows * 8;

        // Alignment check: Marlin requires N % 64 == 0 and K % 16 == 0
        if out_features % 64 != 0 || in_features % 16 != 0 {
            tracing::warn!("Skipping Marlin reformat for layer with N={out_features}, K={in_features} (alignment)");
            return Ok(false);
        }

        // Reformat on CPU then transfer to device
        let qw_cpu = self.qweight.to_device(&Device::Cpu)?;
        let qw_data: Vec<u32> = qw_cpu.to_vec1()?; // Flatten to 1D

        let marlin_data = reformat_gptq_to_marlin(&qw_data, in_features, out_features);
        let marlin_tensor = Tensor::from_vec(marlin_data, (in_features / 16, out_features / 64, 128), &Device::Cpu)?
            .to_device(self.qweight.device())?;

        self.qweight_marlin = Some(marlin_tensor);
        Ok(true)
    }
    ```

    Implement `reformat_gptq_to_marlin(qw: &[u32], K: usize, N: usize) -> Vec<u32>`:
    - For each 16xN tile of the weight matrix (16 input features, N output features):
      - For each 16x64 sub-tile within that row of tiles:
        - Pack the INT4 values into contiguous tile layout [K/16, N/64, 128]
    - Use the simplified tile reformat approach (contiguous 16x64 tiles, not full Marlin interleaving). The CUDA kernel handles extraction. Full interleaving is a Phase 2 optimization.

    **Part B: Forward dispatch (in quantization.rs)**

    Update the `forward()` method. The mechanism is: store `Arc<dyn KernelBackend>` in GptqLinear (the `backend` field added in Plan 02), call `self.backend.marlin_gemm()` in forward. No thread-local, no static, no `marlin_gemm_direct()`.

    ```rust
    fn forward(&self, xs: &Tensor) -> Result<Tensor> {
        // Marlin fast path: requires both reformatted weights AND a backend
        if let (Some(ref qw_marlin), Some(ref backend)) = (&self.qweight_marlin, &self.backend) {
            return backend.marlin_gemm(xs, qw_marlin, &self.scales, &self.qzeros, self.group_size);
        }

        // Naive fallback: dequantize then matmul
        let w = self.dequantize(xs.dtype())?;
        let result = xs.matmul(&w.t()?)?;
        match &self.bias {
            Some(b) => result.broadcast_add(b),
            None => Ok(result),
        }
    }
    ```

    **Part C: Model-load activation (in safetensors_loader.rs)**

    Add a post-construction step in `load_model_from_safetensors()` that activates Marlin for all GPTQ layers:

    ```rust
    // After model construction, activate Marlin for GPTQ layers on CUDA
    if device.is_cuda() {
        if let Some(backend) = &kernel_backend {
            let backend_arc = Arc::clone(backend);
            let mut marlin_count = 0;
            // Iterate all GptqLinear layers in the model and call reformat_for_marlin
            for layer in model.layers_mut() {
                for linear in layer.quantized_linears_mut() {
                    if let MaybeQuantizedLinear::Gptq(ref mut gptq) = linear {
                        gptq.backend = Some(Arc::clone(&backend_arc));
                        if gptq.reformat_for_marlin(backend_arc.as_ref())? {
                            marlin_count += 1;
                        }
                    }
                    if let MaybeQuantizedLinear::Awq(ref mut awq) = linear {
                        awq.inner_mut().backend = Some(Arc::clone(&backend_arc));
                        if awq.inner_mut().reformat_for_marlin(backend_arc.as_ref())? {
                            marlin_count += 1;
                        }
                    }
                }
            }
            if marlin_count > 0 {
                tracing::info!("Activated Marlin fused kernel for {marlin_count} quantized layers");
            }
        }
    }
    ```

    NOTE: The exact iteration API (layers_mut, quantized_linears_mut) depends on the model trait. If SafetensorsLlamaModel doesn't have these methods, add them. The key requirement is that every GptqLinear layer gets its `backend` set and `reformat_for_marlin()` called. Without this call site, qweight_marlin stays None and Marlin never activates.
