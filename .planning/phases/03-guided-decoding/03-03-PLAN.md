<objective>
Add LRU eviction to IndexCache and expose Prometheus cache metrics.

Purpose: The IndexCache is currently an unbounded HashMap that grows without limit. Production workloads with many distinct schemas/regex patterns would leak memory. LRU eviction with configurable max entries (default 256) bounds memory usage. Prometheus metrics (hits, misses, size, evictions) enable monitoring cache effectiveness.

Output: LRU-backed IndexCache in guided.rs, cache metric counters in ServerMetrics, Prometheus exposition lines in /metrics.
</objective>

  <action>
1. Add `lru = "0.12"` dependency to crabinfer-core/Cargo.toml (lru crate is simple, well-maintained, provides LruCache with cap).

2. In guided.rs, replace IndexCache internals:
   - Replace `HashMap<String, Arc<Index>>` with `lru::LruCache<String, Arc<Index>>`
   - Add `max_entries: usize` field (default 256)
   - Add a `CacheStats` struct with AtomicU64 counters: `hits`, `misses`, `evictions`, accessed via `&self.stats`
   - `new()` signature becomes `new(vocabulary: Vocabulary, max_entries: usize)` — but also provide `new_default(vocabulary: Vocabulary)` that uses 256
   - `get_or_create()` now:
     a. `cache.get(regex)` — if hit, increment stats.hits, return Arc::clone
     b. If miss, increment stats.misses. Build Index. If cache is at capacity before insert, increment stats.evictions. `cache.put(regex, index)`.
     c. Return the new index.
   - Add `pub fn stats(&self) -> CacheStatsSnapshot` method returning a plain struct with `hits: u64, misses: u64, evictions: u64, size: usize`
   - `CacheStatsSnapshot` is a simple Copy struct (not atomic) for reading.

3. Update the single call site in engine_loop.rs that creates `IndexCache::new(vocab)` to use `IndexCache::new_default(vocab)` (or keep the same name and add the default parameter — use your judgment on API ergonomics).

4. Update existing tests:
   - `test_index_cache_deduplication` should still pass (LRU preserves recent entries)
   - Add `test_lru_eviction`: create cache with max_entries=2, insert 3 patterns, verify first is evicted
   - Add `test_cache_stats_tracking`: verify hits/misses/evictions counters after a sequence of get_or_create calls
  </action>
