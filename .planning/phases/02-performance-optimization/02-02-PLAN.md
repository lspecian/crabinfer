**TensorArena** — A bump-pointer arena for CPU-side temporary byte buffers used when building batch inputs (e.g., collecting token IDs, positions, slot mappings into contiguous arrays before creating tensors):

```rust
pub struct TensorArena {
    buffer: Vec<u8>,
    offset: usize,
}

impl TensorArena {
    pub fn new(capacity_bytes: usize) -> Self { ... }

    /// Allocate `size` bytes from the arena. Returns a mutable slice.
    /// Returns Err if remaining capacity is insufficient.
    pub fn allocate(&mut self, size: usize) -> candle_core::Result<&mut [u8]> { ... }

    /// Reset the arena for the next step. O(1) — just resets the offset.
    pub fn reset(&mut self) { self.offset = 0; }

    /// Remaining bytes available.
    pub fn remaining(&self) -> usize { self.buffer.len() - self.offset }

    /// Convenience: allocate a typed slice of `count` elements.
    pub fn allocate_slice<T: Copy>(&mut self, count: usize) -> candle_core::Result<&mut [T]> {
        let size = count * std::mem::size_of::<T>();
        let bytes = self.allocate(size)?;
        // Safety: bytes are properly aligned (Vec<u8> is at least 8-byte aligned on 64-bit)
        // and the lifetime is tied to &mut self
        Ok(unsafe { std::slice::from_raw_parts_mut(bytes.as_mut_ptr() as *mut T, count) })
    }
}
```

**TensorBufferPool** — Pre-allocates a set of reusable tensors at engine init time. Uses a shape-keyed map of free lists:

```rust
use std::collections::HashMap;
use candle_core::{DType, Device, Tensor};

/// Key for buffer pool lookup: (shape_as_vec, dtype).
type PoolKey = (Vec<usize>, DType);

pub struct TensorBufferPool {
    /// Free tensors available for checkout, keyed by (shape, dtype).
    free: HashMap<PoolKey, Vec<Tensor>>,
    device: Device,
}

impl TensorBufferPool {
    /// Create a pool and pre-allocate `count` tensors for each (shape, dtype) pair.
    pub fn new(
        specs: &[(&[usize], DType, usize)],  // (shape, dtype, count)
        device: &Device,
    ) -> candle_core::Result<Self> { ... }

    /// Check out a tensor with the given shape and dtype.
    /// Returns a pre-allocated tensor if available, otherwise allocates a new one.
    pub fn checkout(&mut self, shape: &[usize], dtype: DType) -> candle_core::Result<Tensor> {
        let key = (shape.to_vec(), dtype);
        if let Some(list) = self.free.get_mut(&key) {
            if let Some(tensor) = list.pop() {
                return Ok(tensor);
            }
        }
        // Fallback: allocate new (this is the slow path, should be rare after warmup)
        Tensor::zeros(shape, dtype, &self.device)
    }

    /// Return a tensor to the pool for reuse.
    pub fn checkin(&mut self, tensor: Tensor) {
        let key = (tensor.dims().to_vec(), tensor.dtype());
        self.free.entry(key).or_default().push(tensor);
    }
}
```

Key design points:
- TensorArena is for CPU-side scratch memory (building u32 arrays for token IDs, positions, etc. before copying to device)
- TensorBufferPool is for device-side tensor reuse (the actual Tensor objects that go into BatchInput)
- Both are owned by ServingEngineInner and reset/recycled each iteration

**3. Update batch building to use pool:**

Find the function that creates BatchInput from scheduler output (likely `build_batch_input` or similar). Instead of using `Tensor::from_vec(...)` or `Tensor::new(...)` for the batch tensors:

a. Checkout a tensor from the pool: `let mut input_ids_buf = self.buffer_pool.checkout(&[total_tokens], DType::U32)?;`
b. Copy data into the tensor (using Tensor::copy_ or by creating a new tensor from the collected vec and then checking in the old one)
c. After the forward pass completes, checkin all batch tensors back to the pool

Since candle's Tensor API doesn't support in-place mutation easily from Rust (no `copy_` method), the practical approach is:
- Use `Tensor::from_vec` to create batch tensors from the gathered data (this is CPU-side, cheap)
- The buffer pool is primarily useful for device-side intermediate tensors. For batch input tensors that are created from CPU data each step, the pool can hold the max-sized tensors and we `narrow` them to the actual batch size.
- Alternative: Use `Tensor::from_slice` to create from the arena's slice, avoiding Vec allocation.

The most impactful optimization is combining TensorArena for gathering data (no Vec allocations) with direct Tensor creation from the arena slice:

```rust
// Instead of:
let mut ids = Vec::with_capacity(total_tokens);
for seq in scheduled { ids.extend(&seq.token_ids); }
let input_ids = Tensor::new(&ids[..], &self.device)?;

// Use arena:
let ids_slice = self.arena.allocate_slice::<u32>(total_tokens)?;
let mut offset = 0;
for seq in scheduled {
    ids_slice[offset..offset+seq.len()].copy_from_slice(&seq.token_ids);
    offset += seq.len();
}
let input_ids = Tensor::from_slice(ids_slice, total_tokens, &self.device)?;
self.arena.reset(); // Ready for next step
```
