**KernelBackend trait (backend.rs):**

Add a new optional method `fused_layernorm_linear` following the same pattern as `fused_rmsnorm`:

```rust
/// Fused RMSNorm + linear projection.
///
/// Computes `output = rmsnorm(x, weight, eps) @ linear_weight` in a single
/// kernel pass, eliminating the intermediate normalized tensor in global memory.
///
/// # Arguments
/// - `x`: `[num_rows, hidden_size]` input
/// - `norm_weight`: `[hidden_size]` RMSNorm scale
/// - `eps`: normalization epsilon
/// - `linear_weight`: `[hidden_size, out_features]` projection weight (column-major for matmul)
///
/// # Returns
/// `[num_rows, out_features]`
fn fused_layernorm_linear(
    &self,
    x: &Tensor,
    norm_weight: &Tensor,
    eps: f32,
    linear_weight: &Tensor,
) -> Result<Tensor> {
    // Default: unfused path
    let normed = candle_nn::ops::rms_norm(x, norm_weight, eps)?;
    normed.matmul(&linear_weight.t()?)
}
```

Update the existing Wave 0 test stubs in backend.rs to be real tests that verify the default implementation works correctly:

- `test_fused_layernorm_linear_matches_unfused`: Verify default impl output matches manual `rms_norm(x) @ W^T` within 1e-3 tolerance.

**CUDA kernel (paged_attention.cu):**

Add `fused_layernorm_linear_f16` kernel that:
1. Each block processes one row of x
2. Computes RMS norm in shared memory (sum of squares, sqrt, normalize)
3. Immediately computes dot product of normalized row with each output column
4. Writes result directly to output tensor

Grid: `(num_rows, 1, 1)` with 256 threads per block. Each thread handles `hidden_size/256` elements for norm, then contributes to output columns via shared memory reduction.

NOTE: This kernel is compile-tested only (NVRTC compilation). No CUDA GPU available in test environment.

**RmsNorm helper (models/mod.rs):**

Add a new method to RmsNorm that combines norm + linear in one backend call:

```rust
/// Fused RMSNorm + linear projection.
///
/// On CUDA, this runs in a single kernel. On CPU/Metal, falls back to
/// sequential norm + matmul via the default trait implementation.
pub fn forward_linear_fused(
    &self,
    x: &Tensor,
    linear: &MaybeQuantizedLinear,
    backend: &dyn KernelBackend,
) -> Result<Tensor> {
    // Only use fused path for dense (non-quantized) linear layers
    // because the fused kernel expects F16 weight matrices.
    match linear {
        MaybeQuantizedLinear::Dense(weight) => {
            backend.fused_layernorm_linear(x, &self.weight, self.eps, weight)
        }
        _ => {
            // Quantized or GGUF linear: use unfused path
            let normed = backend.fused_rmsnorm(x, &self.weight, self.eps)?;
            linear.forward(&normed)
        }
    }
}
```

This requires checking MaybeQuantizedLinear's variants. Look at the existing MaybeQuantizedLinear enum in quantization.rs to understand its variants. If it doesn't have a variant that exposes the raw weight tensor, the fused path will only be available when the linear is a plain dense layer. Add a `weight_tensor()` method to MaybeQuantizedLinear if needed that returns `Option<&Tensor>` for the Dense variant.
