Purpose: Eliminate the `CUDA_ERROR_STREAM_CAPTURE_UNSUPPORTED` error that causes a 30-40% performance gap vs vLLM. After this plan, CUDA graphs capture successfully for both decode and prefill batch sizes.

Output: Working CUDA graph capture with I32 metadata tensors, partial capture error handling, and direct GPU safetensors loading.
</objective>

**3. Add dtype assertion to copy_inputs:**

In `copy_inputs()` (line ~433-450), add assertions before `copy_tensor_data` calls to catch dtype mismatches early:
```rust
assert_eq!(
    entry.buffers.slot_mapping.dtype(),
    slot_mapping.dtype(),

    entry.buffers.slot_mapping.dtype(),
    slot_mapping.dtype()

```
Do the same for `context_lens` and `block_tables`. This prevents the silent memory corruption pitfall described in RESEARCH.md Pitfall 5.

**4. Implement partial capture error handling:**

Review `warmup_cuda_graphs()` and `capture_graph_for_batch_size()`. The warmup loop already handles per-batch-size errors (match on result, warn and continue). Verify this pattern is robust:
- If `capture_graph_for_batch_size` returns `Err`, the loop must `tracing::warn!` and continue to the next batch size (NOT return the error).
- Ensure `end_capture` is always called even if the forward pass errors. If the current code calls forward then end_capture sequentially, add a safety check: if forward returns Err, still call end_capture before returning the error from `capture_graph_for_batch_size`. This prevents the stream from remaining in capture mode (Pitfall 1 from RESEARCH.md).

Pattern for safe capture:
```rust
let forward_result = model.forward(...);
// ALWAYS end capture, regardless of forward result
let graph_result = stream.end_capture(...);
// Now check both results
forward_result?;
let graph = graph_result?;
```
