## Accomplishments

- Replaced all CPU-first I32 tensor workarounds in capture region with direct GPU creation
- Added dtype assertions to copy_inputs preventing silent memory corruption (Pitfall 5)
- Added direct GPU loading path for safetensors I32/I16 tensors with CPU fallback
- Verified capture region is clean: zero to_device() calls between begin_capture and end_capture

## Files Created/Modified

- `crabinfer-core/src/serving/engine_loop.rs` - Replaced CPU-first I32 workarounds in warmup_eager_pass and capture_graph_for_batch_size with direct GPU creation, wired metadata_dtype through config
- `crabinfer-core/src/serving/safetensors_loader.rs` - Added direct GPU loading path for CUDA devices with CPU fallback

## Decisions Made
- I32 as default metadata_dtype: matches vLLM convention, halves memory for metadata tensors, sufficient for block indices in single-GPU deployments
- Dtype assertions in copy_inputs use `assert_eq!` (panic) rather than returning Result errors, since dtype mismatches are programming errors that should fail fast
- Safetensors loader attempts direct GPU loading first, falls back to CPU with tracing::debug! log on failure, ensuring no regression for edge cases
