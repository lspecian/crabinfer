## Gaps Summary

Two gaps block full goal achievement:

**Gap 1 — gpu_memory.rs VRAM estimation (FAILED)**

`estimate_weights_memory()` uses a hardcoded `total_params * 2` (2 bytes per param) regardless of the resolved serving dtype. When a user runs with `--dtype auto` on CPU or `--dtype f32`, the weight VRAM is underestimated by 2x — the profiler behaves as if weights are BF16 when they are F32. Plan 02 Task 2 explicitly specified adding a `weight_dtype_bytes: usize` parameter to `profile_gpu_memory` and threading `serving_dtype.size_in_bytes()` from `engine_loop.rs`, but this was acknowledged as deferred in SUMMARY-02 (`gpu_memory.rs VRAM estimation update was not included`).

Root cause: Single gap from one deferred implementation task (Plan 02 Task 2 step 1-3).

**Gap 2 — Missing VRAM savings INFO log (PARTIAL)**

The startup INFO log `"Serving dtype {:?}: estimated {:.0}% weight memory savings vs F32"` was specified in Plan 02 Task 2 step 4 but not implemented. This is an observability gap, not a functional correctness gap.

These two gaps share a root cause (Plan 02 Task 2 was only partially executed). A single focused fix — adding `weight_dtype_bytes` to `profile_gpu_memory` and the savings log in `engine_loop.rs` — would close both gaps.
