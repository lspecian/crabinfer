## Human Verification Required

### 1. BF16 VRAM halving on H100

**Test:** Run `crabinfer-server --model /path/to/Qwen3-8B-safetensors --dtype bf16` on an H100 with nvidia-smi monitoring.
**Expected:** Model weight VRAM usage ~16GB (halved from ~32GB for FP32); GPU memory profile log shows weights ~16GB; startup log shows "Serving dtype BF16: estimated 50% weight memory savings vs F32".
**Why human:** Requires actual H100 GPU and a real 8B FP32 safetensors model.

### 2. Auto dtype selection on Ampere GPU

**Test:** Run with `--dtype auto` on an A100 or H100. Inspect startup logs.
**Expected:** Log line: `Auto-selecting serving dtype: BF16 (sm_80+: Ampere or newer)`
**Why human:** `detect_best_dtype()` CUDA compute capability path is gated behind `#[cfg(feature = "cuda")]` and cannot be exercised in a no-GPU build environment.

### 3. BF16 rejection on pre-Ampere GPU

**Test:** Run with `--dtype bf16` on a V100 (sm_70).
**Expected:** Server startup fails with: `BF16 requires Ampere (sm_80+) GPU, detected sm_70. Use --dtype f16 or --dtype auto instead.`
**Why human:** Requires a V100 or Turing GPU.

### 4. Inference correctness in BF16

**Test:** Run a generation request against the BF16-loaded model. Compare output quality to F32.
**Expected:** Coherent, correct outputs (minor numerical differences acceptable; no NaN/Inf artifacts).
**Why human:** Numerical correctness requires running the forward pass on actual hardware.
