# Plan 01.2-02: Weight Casting in Safetensors Loader Summary

**Dtype-parameterized weight loading with BF16/F16 casting, FP32 norm preservation, cross-cast protection, and quantized model bypass across all model architectures**

## Performance

- **Duration:** ~8 min
- **Tasks:** 2
- **Files modified:** 5

## Accomplishments
- load_tensor() now accepts dtype parameter; casts F32 weights to BF16/F16 at load time
- load_tensor_fp32() always returns FP32 for norm/embedding layers (DTYPE-04)
- Cross-cast protection: BF16↔F16 skipped with INFO log to avoid precision loss
- Quantized models (GPTQ/AWQ) bypass dtype casting — packed weights stay untouched
- All 4 model architectures updated: Llama/Qwen (inline), DeepSeek, Mistral, Phi3
- Server resolves serving_dtype before model loading and passes concrete DType
- Wave 0 test stubs replaced with real assertions (3 tests)

## Task Commits

1. **Task 1: Loader + server changes** - `69737ef` (feat)
2. **Task 2: Model architecture updates** - `1c05b21` (feat)

## Files Created/Modified
- `crabinfer-core/src/serving/safetensors_loader.rs` - Dtype-parameterized loading, cross-cast, FP32 preservation
- `crabinfer-core/src/serving/models/deepseek.rs` - serving_dtype threading, FP32 norms
- `crabinfer-core/src/serving/models/mistral.rs` - serving_dtype threading, FP32 norms
- `crabinfer-core/src/serving/models/phi3.rs` - serving_dtype threading, FP32 norms
- `crabinfer-server/src/lib.rs` - Resolve serving dtype, pass to model loader

## Decisions Made
- Cross-cast between half-precision formats (BF16↔F16) skipped rather than erroring
- lm_head always loaded as FP32 since it's tied to embed_table
- GPTQ/AWQ models use F32 for weight_dtype to protect packed data
