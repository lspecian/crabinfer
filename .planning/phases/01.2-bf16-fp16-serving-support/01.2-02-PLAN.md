<objective>
Thread serving dtype through the safetensors model loader so weights are cast to BF16/F16, with FP32 preservation for norm/embedding layers, cross-cast protection, and quantized model bypass.

Purpose: This is where the actual VRAM savings happen -- loading 8B model weights in BF16 instead of FP32 halves weight memory from ~32GB to ~16GB.
Output: Dtype-aware weight loading, accurate VRAM estimation, complete end-to-end dtype pipeline.
</objective>

  <behavior>
    - load_tensor(weights, "proj.weight", &Device::Cpu, DType::BF16) returns a BF16 tensor
    - load_tensor_fp32(weights, "norm.weight", &Device::Cpu) returns FP32 regardless
    - load_tensor with BF16 target on a tensor already stored as BF16 returns BF16 (no-op)
    - load_tensor with F16 target on a tensor stored as BF16 logs INFO and returns BF16 (no cross-cast)
    - load_tensor with BF16 target on F32 tensor returns BF16 (the primary use case)
    - Quantized models (GPTQ/AWQ) skip dtype casting entirely
  </behavior>
  <action>
**safetensors_loader.rs changes:**

1. **Update `load_tensor` signature** to accept `dtype: DType` parameter:
   ```rust
   pub fn load_tensor(
       weights: &HashMap<String, Tensor>,
       name: &str,
       device: &Device,
       dtype: DType,
   ) -> Result<Tensor>
   ```
   Implementation: After `to_device(device)?`, check the tensor's current dtype:
   - If current dtype == target dtype: return as-is
   - If current dtype is F32 and target is F16 or BF16: apply `.to_dtype(dtype)` (downcast)
   - If current dtype is F16 or BF16 and target is a DIFFERENT half-precision: log INFO "Weight '{name}' is already {current:?} on disk; skipping cross-cast to {dtype:?}" and return with current dtype
   - Otherwise: apply `.to_dtype(dtype)` (handles all other cases)

2. **Add `load_tensor_fp32` convenience function**:
   ```rust
   pub fn load_tensor_fp32(
       weights: &HashMap<String, Tensor>,
       name: &str,
       device: &Device,
   ) -> Result<Tensor> {
       load_tensor(weights, name, device, DType::F32)
   }
   ```

3. **Update `load_linear` signature** to accept `dtype: DType`:
   ```rust
   pub fn load_linear(
       weights: &HashMap<String, Tensor>,
       name: &str,
       device: &Device,
       quantization: QuantizationMethod,
       dtype: DType,
   ) -> Result<MaybeQuantizedLinear>
   ```
   Pass dtype through to load_tensor.

4. **Update `load_model_from_safetensors_with_backend` signature** to accept `serving_dtype: DType`:
   ```rust
   pub fn load_model_from_safetensors_with_backend(
       model_dir: &Path,
       device: &Device,
       quantization: QuantizationMethod,
       kernel_backend: Option<Arc<dyn KernelBackend>>,
       serving_dtype: DType,
   ) -> Result<Box<dyn ModelRunner>>
   ```

5. **Update `load_model_from_safetensors` wrapper** to accept `serving_dtype: DType` and pass through. Default behavior preserved since callers pass `DType::F32` for the same behavior as before.

6. **Inside `load_model_from_safetensors_with_backend`**: Determine the effective weight dtype:
   ```rust
   let weight_dtype = match effective_quantization {
       QuantizationMethod::None => serving_dtype,
       _ => DType::F32,  // quantized weights have their own format
   };
   ```
   Then pass `weight_dtype` to all `load_linear` calls and `DType::F32` to all `load_tensor` calls for norm/embedding weights.

   Specifically update the internal `load_proj` closure (or wherever linear projection weights are loaded) to use `weight_dtype`. Keep all norm/embedding loads explicitly passing `DType::F32`:
   - `model.embed_tokens.weight` -> `load_tensor(weights, name, device, DType::F32)` (FP32 preservation per DTYPE-04)
   - `model.norm.weight` -> `load_tensor(weights, name, device, DType::F32)`
   - `*.input_layernorm.weight` -> `load_tensor(weights, name, device, DType::F32)`
   - `*.post_attention_layernorm.weight` -> `load_tensor(weights, name, device, DType::F32)`
   - QKV bias and QK norm paths (lines 1054-1075): DO NOT TOUCH. They already use inline `.to_dtype(DType::F32)`.
   - `lm_head` tied weight: when created from `embed_table.clone()`, do NOT apply serving dtype cast. The embed_table is FP32 and the QMatMul::Tensor path handles mixed dtypes.
   - All `load_linear` / `load_proj` calls for Q/K/V/O projections and FFN (gate/up/down): pass `weight_dtype`.

7. **Log at INFO** when loading begins:

   ```rust
   );
   ```
